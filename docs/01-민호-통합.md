## 겪어보고 알게 된 함정

나중에 또 만날 수 있어서 적어둡니다.

| 증상 | 원인 |
|---|---|
| 조용히 빈 배열이 온다 | RLS 정책 누락. **에러가 안 납니다** |
| "AI는 성공했는데 저장이 안 됨" | 해당 테이블에 INSERT 정책이 없음 (`action_ai_metadata` 에서 실제로 발생) |
| 여러 행 insert 시 DEFAULT 무시 | PostgREST가 컬럼을 합치면서 빠진 키를 **명시적 NULL** 로 보냄. 모든 컬럼을 채울 것 |
| 뷰에서 온 값이 전부 `\| null` | Postgres가 뷰의 NOT NULL 을 보장 못 함. `?? 기본값` 으로 받기 |
| AI가 400 을 돌려줌 | `response_format: json_object` 인데 프롬프트에 "json" 이라는 낱말이 없음 |
| 활동일이 지났는데 상태가 그대로 | 상태 전환이 lazy 라 아무도 안 열면 안 바뀜. Activity(만든 액션)에서 확인함 |

## 반드시 지킬 것

1. params 와 searchParams 는 Promise 다. 반드시 await 한다.
   서버에서 cookies() 도 await 이 필요하다 (lib/supabase/server.ts 가 처리해 둠).

2. 화면 코드는 lib/queries/ 와 lib/mutations.ts 함수만 쓴다.
   새 조회가 필요하면 lib/queries/ 에 함수를 추가하고, 화면에서 직접 쿼리하지 않는다.

3. 쓰기 함수는 { ok: true, data } 또는 { ok: false, message } 를 돌려준다.
   message 는 그대로 사용자에게 보여주는 한국어다.

4. 스키마를 바꿀 때 supabase/01~03 파일을 수정하지 않는다.
   새 번호 파일(06_....sql)로 쌓는다. 이미 적용된 DB 와 새 DB 가 달라지기 때문이다.
   바꾼 뒤 npm run verify:db 를 돌리고, 타입을 다시 생성한다.

5. lib/types/database.ts 는 자동 생성 파일이다. 손으로 수정하지 않는다.
   짧은 별칭이 필요하면 lib/types/db.ts 에 추가한다.

6. RLS 를 켠 테이블에는 필요한 동작마다 정책이 있어야 한다.
   정책이 없는 동작은 에러 없이 조용히 거부된다.
   새 테이블을 만들면 SELECT/INSERT/UPDATE/DELETE 중 필요한 것을 빠짐없이 만든다.

7. 여러 행을 한 번에 insert 할 때는 모든 컬럼을 빠짐없이 채운다.
   PostgREST 가 컬럼 목록을 합치면서 빠진 키를 명시적 NULL 로 보내
   DB 의 DEFAULT 가 적용되지 않는다.

8. 뷰에서 온 값은 타입이 전부 nullable 이다. ?? 기본값 으로 받는다.
   Postgres 가 뷰의 NOT NULL 을 보장하지 못하기 때문이다.

9. AI 프롬프트에는 "json" 이라는 낱말이 반드시 들어가야 한다.
   response_format 이 json_object 인데 없으면 OpenAI 가 400 을 돌려준다.
   (lib/openai.ts 가 자동으로 덧붙이지만 프롬프트에도 명시하는 게 좋다)
   프롬프트를 고치면 promptVersion 을 올린다. ai_runs 기록이 발표 근거가 된다.

10. 트랜잭션이 필요한 작업은 Postgres 함수(RPC)로 만든다.
    supabase.from().insert() 를 여러 번 부르는 건 트랜잭션이 아니다.
    정원 검증 같은 동시성 문제는 FOR UPDATE 로 행을 잠근다.

11. 알림은 남에게 만들어 주는 것이라 RLS 로는 넣을 수 없다.
    SECURITY DEFINER 함수 안에서 만들거나 Service Role 로 만든다.
    event_key 를 UNIQUE 로 두어 중복 생성을 막는다.

12. SUPABASE_SERVICE_ROLE_KEY 와 OPENAI_API_KEY 에 NEXT_PUBLIC_ 접두사를
    절대 붙이지 않는다. 붙이는 순간 브라우저로 전송된다.
    lib/openai.ts 는 server-only 다. 클라이언트 컴포넌트에서 import 하지 않는다.

13. 사용자에게 보이는 문구와 코드 주석은 한국어로 쓴다.
    에러 메시지는 무엇이 잘못됐고 어떻게 고치는지 알려준다.

14. 새 파일·새 쿼리·새 상수를 만들기 전에, 이미 있는 것을 먼저 찾아 쓴다.
