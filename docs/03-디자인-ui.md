## 지금 상태

**기능은 전부 동작합니다. 디자인이 밋밋합니다.** 만드는 일이 아니라 **다듬는 일**입니다.

| 디자인 토큰 | `tailwind.config.ts` · `app/globals.css` · `app/layout.tsx` | 최소한만 설정됨 |

## ⚠️ 절대 바꾸면 안 되는 것

**`ActionCard`의 props 이름과 개수.** 다섯 화면이 이 컴포넌트를 씁니다.

```tsx
<ActionCard action={...} showStatus footer={...} />
```

보이는 모습(색·간격·타이포·레이아웃)은 **마음껏 바꾸셔도 됩니다.** props만 그대로 두세요.

**`QuotaProgress`의 계산 로직.** 모집 수량 표시 규칙이 들어 있습니다.

```tsx
// 이 컴포넌트 안의 getQuotaState() 호출부는 건드리지 마세요
// className 과 마크업 구조만 바꾸세요
```

왜냐하면 규칙이 두 가지로 갈리기 때문입니다.

```
최소 10명형   →  15명 참여  ·  퍼센트를 쓰지 않음 (150%는 의미가 없음)
3~5명형       →  4 / 5명    ·  퍼센트를 씀
              →  최소를 넘기면 분모가 3에서 5로 바뀜
```

숫자를 직접 조합하면 이 규칙이 깨집니다.

## 첫 작업 제안

### ① 디자인 토큰 정리 (반나절)

`tailwind.config.ts`에 목업의 색과 크기를 넣습니다.

```ts
theme: {
  extend: {
    colors: {
      brand: { DEFAULT: '#...', soft: '#...' },
    },
  },
},
```

> ⚠️ `neutral` 계열은 다른 사람들이 이미 쓰고 있습니다. **이름을 바꾸지 말고 추가만** 하세요.

폰트를 Pretendard로 바꾸려면 `app/layout.tsx`에 웹폰트 링크를 추가하고 `app/globals.css`의 `--font-sans`를 고치면 됩니다.

### ② ActionCard 다듬기 (반나절)

`components/ui/ActionCard.tsx`. **홈·Discover·Activity·저장목록·프로필 다섯 곳에 동시에 반영됩니다.** 가성비가 제일 좋은 작업입니다.

지금은 이미지·제목·요약·날짜·아바타·카운트가 다 들어 있지만 배치가 단순합니다.

### ③ 액션 상세 (하루)

`app/action/[id]/page.tsx`. **발표에서 가장 오래 보이는 화면**입니다.

이미지 캐러셀 · 모집 현황 · 일정/장소 · 안내사항 · 좋아요/저장 · 하단 고정 버튼 순서로 되어 있습니다.

## 반드시 지킬 것

1. params 와 searchParams 는 Promise 다. 반드시 await 한다.
   const { id } = await params;

2. 데이터 읽기는 lib/queries/ 의 함수, 쓰기는 lib/mutations.ts 의 함수만 쓴다.
   화면에서 supabase.from(...) 이나 supabase.rpc(...) 를 직접 호출하지 않는다.
   필요한 함수가 없으면 새로 만들지 말고 "없다"고 알려준다.

3. 쓰기 함수는 { ok: true, data } 또는 { ok: false, message } 를 돌려준다.
   message 는 그대로 사용자에게 보여주면 되는 한국어다. try/catch 를 쓰지 않는다.

4. 화면 문구는 lib/constants/index.ts 에서 가져온다. 문자열을 직접 적지 않는다.
   ACTION_STATUS_LABEL · PARTICIPATION_STATUS_LABEL · CATEGORIES ·
   AVAILABLE_TIMES · GENDER_LABEL · GENDER_REQUIREMENT_LABEL · LIMITS · UPLOAD

5. 모집 수량 표시는 lib/utils/quota.ts 의 함수를 쓴다. 숫자를 직접 조합하지 않는다.
   getQuotaState · describeTarget · describeResult · describeResultCount · meetsGender
   최소 인원형(MINIMUM)에는 퍼센트를 쓰지 않는다. 15/10=150%는 의미가 없다.
   정해진 인원형(RANGE)은 최소를 넘기면 분모가 min 에서 max 로 바뀐다.

6. 날짜 표시는 lib/utils/date.ts 를 쓴다.
   formatDate · formatDateShort · formatTime · formatActivityPeriod · formatRelative

7. 이미 있는 공통 컴포넌트를 쓴다. 비슷한 것을 새로 만들지 않는다.
   components/ui/     Button Badge Chip EmptyState Toast Avatar ActionCard
                      ImageUploader RegionPicker UserList LogoutButton
                      ToggleButtons(LikeButton SaveButton FollowButton)
   components/layout/ Header BottomNav
   components/action/ QuotaProgress ActionGallery AddressBox

8. ActionCard 의 props 이름과 개수는 절대 바꾸지 않는다.
   다섯 화면이 이 컴포넌트를 쓴다. 보이는 모습만 바꾼다.
   QuotaProgress 의 getQuotaState 호출부도 바꾸지 않는다. 마크업과 className 만 바꾼다.

9. 서버 컴포넌트가 기본이다. 'use client' 는 훅·이벤트·브라우저 API 가
   필요할 때만 쓴다. 데이터 조회는 서버에서 하고 버튼만 클라이언트로 뺀다.

10. 목록 화면에는 빈 상태(EmptyState)를 반드시 넣는다. 다음 행동 버튼을 함께 준다.

11. 사용자에게 보이는 문구와 코드 주석은 한국어로 쓴다.

12. 홈과 액션 상세는 비회원도 볼 수 있다. user 가 null 일 수 있으므로
    user!.id 처럼 강제 단언하지 않는다. user?.id ?? null 로 넘긴다.

13. 새 파일·새 쿼리·새 상수를 만들기 전에, 이미 있는 것을 먼저 찾아 쓴다.
