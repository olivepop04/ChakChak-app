# Discover 대화 문구 개선 설계

## 목표

Discover를 설문조사처럼 느껴지는 고정 문답이 아니라, 사용자의 답변을 짧게 받아주며 잘 맞는 Action을 함께 찾는 친절한 대화로 개선합니다.

## 유지할 결정

- 사용자는 정확히 5개의 질문에 답한 뒤 추천을 받습니다.
- 첫 질문은 재능 활용 여부입니다.
- 재능을 활용하면 사용할 재능을, 활용하지 않으면 참여 방식을 묻습니다.
- 이후 모임 규모, 분야 선호, 이동 가능 범위를 묻습니다.
- 후보 조회, 조건 완화, 점수 계산, 상위 3개 선정, 추천 이유 생성 구조는 유지합니다.
- DB 스키마는 변경하지 않습니다.

참고 프롬프트의 4~6개 가변 질문과 AI의 질문 순서 선택은 위의 최근 팀 결정과 충돌하므로 이번 범위에 포함하지 않습니다.

## 대화 경험

### 첫 질문

처음부터 조건을 묻지 않고 닉네임을 포함한 짧은 환영과 Discover의 역할을 먼저 알립니다. 실제 데이터가 없으면 활동 이력이나 관심사를 아는 것처럼 말하지 않습니다.

예시:

> 반가워요, 지수님. 😊
>
> 몇 가지만 편하게 알려주시면 지수님에게 잘 맞는 액션을 찾아볼게요.
>
> 먼저, 이번에는 가진 재능을 활용할 수 있는 액션을 찾아볼까요?

### 답변 연결

다음 질문 앞에 이전 답변을 짧게 받아주는 한 문장을 붙입니다. 과도하게 칭찬하지 않고, 선택한 내용이 추천에 어떻게 쓰이는지 알려줍니다.

- 재능 활용: 가진 재능을 살릴 수 있는 액션을 찾겠다고 안내
- 재능 미사용: 특별한 재능 없이도 참여할 수 있다고 안심시킨 뒤 참여 방식 질문
- 재능 또는 참여 방식 선택: 선택 내용을 받아준 뒤 모임 규모 질문
- 모임 규모 선택: 선택 내용을 받아준 뒤 분야 선호 질문
- 분야 선호 선택: 선택 내용을 받아준 뒤 마지막 이동 범위 질문

### 개인화

- 프로필에 재능이 있으면 재능명을 문장에 포함해 어떤 재능을 우선할지 확인합니다.
- 참여 이력이 있으면 실제 최근 참여 카테고리를 근거로 분야 선호를 확인합니다.
- 참여 이력이 없으면 프로필 관심 분야를 근거로 질문합니다.
- 근거 데이터가 없으면 일반 문장을 사용합니다.

## 재능 선택지

Discover의 별도 묶음 선택지를 제거하고 `lib/constants/index.ts`의 `SKILLS`를 그대로 사용합니다. 프로필과 Discover가 같은 값을 사용하므로 추천 점수에 잘못 연결되는 일을 막습니다.

## 추천 시작 문장

다섯 답변에서 확실히 확인된 선호만 짧게 요약한 뒤 추천을 시작합니다. 데이터가 없는 내용을 만들어내지 않습니다.

## 조건 완화 안내

지역 또는 관심 분야를 넓혔을 때 내부 처리 설명을 나열하지 않고 다음 문장을 한 번만 표시합니다.

> 말씀해주신 조건에 맞는 액션이 많지 않아 비슷한 조건까지 조금 넓혀서 찾아봤어요. 최대한 비슷한 액션부터 보여드릴게요.

어떤 조건을 완화했는지는 기존 서버 데이터에 그대로 남기되, 사용자 화면에서는 위의 자연스러운 통합 문장으로 안내합니다.

## 오류와 AI 실패

AI 호출이 실패하거나 허용되지 않은 질문을 반환해도 서버의 기본 문구가 같은 대화 흐름을 제공합니다. 질문 순서와 추천 시작 시점은 계속 서버가 통제합니다.

## 테스트

- 첫 질문에 환영과 닉네임이 포함되는지 확인합니다.
- 재능 사용 여부에 따라 다음 질문 연결 문장이 달라지는지 확인합니다.
- 프로필 재능 옵션과 Discover 재능 옵션이 동일한지 확인합니다.
- 신규 사용자와 기존 참여 사용자의 분야 질문이 실제 데이터에 맞게 달라지는지 확인합니다.
- 다섯 답변 후 추천 안내가 확인된 선호를 반영하는지 확인합니다.
- 조건 완화 시 자연스러운 통합 안내가 한 번만 표시되는지 확인합니다.
