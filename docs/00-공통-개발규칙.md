## 1. 화면 파일을 어디에 만드나

`app/` 폴더의 **경로가 곧 웹 주소**입니다.

| 만들 파일 | 웹 주소 |
|---|---|
| `app/page.tsx` | `/` |
| `app/discover/page.tsx` | `/discover` |
| `app/action/[id]/page.tsx` | `/action/아무아이디` |
| `app/action/[id]/join/page.tsx` | `/action/아무아이디/join` |

**전체 주소 목록** (이 밖의 주소를 임의로 만들지 마세요)

| 주소 | 화면 | 담당 |

## 2. 서버 컴포넌트 vs 클라이언트 컴포넌트

**기본은 서버 컴포넌트입니다.** 아무것도 안 쓰면 서버 컴포넌트입니다.

`'use client'`는 **아래 중 하나가 필요할 때만** 파일 맨 위에 씁니다.

- `useState`, `useEffect` 같은 훅
- `onClick`, `onChange` 같은 이벤트
- `window`, `localStorage`

### 권장 구조

데이터를 불러오는 건 서버에서, 버튼만 클라이언트로 떼어냅니다.

```tsx
// app/action/[id]/page.tsx  ← 'use client' 없음 (서버)
import { createClient } from '@/lib/supabase/server';
import { getActionDetail } from '@/lib/queries/actions';
import { LikeButton } from '@/components/ui/LikeButton';  // 이것만 클라이언트

export default async function Page({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params;                       // ★ await 필수
  const supabase = await createClient();
  const { data: { user } } = await supabase.auth.getUser();

  const action = await getActionDetail(supabase, id, user?.id ?? null);
  if (!action) notFound();

  return (
    <main>
      <h1>{action.title}</h1>
      <LikeButton actionId={action.id} initialLiked={action.likedByMe} count={action.likeCount} />
    </main>
  );
}
```

**서버 컴포넌트를 `'use client'`로 만들지 마세요.** 데이터를 못 불러오게 되어 `useEffect` + `fetch`로 다시 짜야 합니다.

## 3. 데이터 읽기

> **`lib/queries/` 의 함수만 부릅니다.**

```tsx
const supabase = await createClient();
const actions = await getActionFeed(supabase, { viewerId: user?.id ?? null });
```

**하면 안 되는 것**

```tsx
// ❌ 화면에서 직접 쿼리 — 사람마다 조건이 달라져서 화면마다 결과가 달라집니다
const { data } = await supabase.from('actions').select('*');
```

필요한 함수가 없으면 **민호에게 요청**하세요. `lib/`은 공유 구역입니다.

## 4. 데이터 쓰기

> **`lib/mutations.ts` 의 함수만 부릅니다.**

모든 함수는 이렇게 돌려줍니다.

```ts
{ ok: true, data: ... }
{ ok: false, message: '「요리 담당」 모집이 완료되었습니다. (3 / 3)' }
```

`message`는 **그대로 사용자에게 보여주면 되는 한국어**입니다. `try/catch`가 필요 없습니다.

```tsx
'use client';
const res = await joinAction(supabase, actionId, items);
if (!res.ok) {
  setError(res.message);   // 그대로 화면에 표시
  return;
}
router.push(`/action/${actionId}/welcome`);
```

### 저장 후 화면 갱신

```tsx
import { useRouter } from 'next/navigation';
const router = useRouter();
// ...저장 성공 후
router.refresh();   // 서버 컴포넌트를 다시 불러온다
```

## 5. 화면 3종 세트 — 반드시 넣기

어떤 목록이든 **세 가지 상태**를 다 만들어야 합니다. 하나라도 빠지면 발표 때 티가 납니다.

```tsx
// 1) 불러오는 중  ← 서버 컴포넌트면 loading.tsx 파일로
// 2) 비어 있음
if (actions.length === 0) {
  return (
    <div className="flex flex-col items-center gap-2 py-16 text-center">
      <p className="text-sm font-medium text-neutral-700">아직 참여한 액션이 없어요</p>
      <p className="text-xs text-neutral-500">마음에 드는 액션을 찾아보세요.</p>
      <Link href="/discover" className="mt-2 text-sm font-medium text-neutral-900 underline">
        액션 찾아보기
      </Link>
    </div>
  );
}
// 3) 정상
```

**빈 상태에는 항상 다음 행동(버튼·링크)을 넣어주세요.** "없습니다"만 있으면 사용자가 막힙니다.

로딩은 같은 폴더에 `loading.tsx`를 만들면 Next.js가 자동으로 보여줍니다.

```tsx
// app/activity/loading.tsx
export default function Loading() {
  return <div className="p-5 text-sm text-neutral-400">불러오는 중…</div>;
}
```

## 6. 글자와 숫자 규칙

### 모집 수량은 반드시 함수로

```tsx
import { getQuotaState, describeTarget } from '@/lib/utils/quota';

const state = getQuotaState(item, item.currentCount);
// state.countLabel → "3 / 5명"  또는  "15명 참여"
// state.hint       → "최소 인원이 충족되었어요."
```

**직접 `${current}/${max}` 로 조합하지 마세요.** 최소 인원형은 퍼센트를 쓰지 않고, 정해진 인원형은 최소를 넘기면 분모가 바뀝니다. 이 규칙이 함수 안에 들어 있습니다.

### 상태 이름은 상수에서

```tsx
import { ACTION_STATUS_LABEL, CATEGORIES } from '@/lib/constants';
ACTION_STATUS_LABEL[action.status]   // 'ACTIVE' → '모집 중'
```

`'모집 중'` 같은 문자열을 화면에 직접 적지 마세요.

### 날짜

```tsx
const d = new Date(action.activityStartAt!);
`${d.getMonth() + 1}월 ${d.getDate()}일`           // 8월 30일
`${d.getHours()}:${String(d.getMinutes()).padStart(2, '0')}`  // 14:00
```

날짜가 `null`일 수 있으니 항상 확인하세요. DRAFT 상태는 날짜가 비어 있습니다.

## 7. 스타일 규칙

- **Tailwind만 씁니다.** 별도 CSS 파일을 만들지 마세요.
- 색은 `neutral` 계열을 기본으로. 강조는 `emerald`(충족·성공), `red`(경고·삭제).
- 공통 컴포넌트(`components/ui/`)가 있으면 **반드시 그걸 쓰세요.** 비슷한 걸 새로 만들면 화면마다 버튼 모양이 달라집니다.
- 모바일 기준입니다. 가로 폭은 `app-shell`이 잡아주니 신경 쓰지 않아도 됩니다.
- 여백은 `gap`으로 주세요. `margin`을 개별로 주면 서로 겹칩니다.

```tsx
<div className="flex flex-col gap-4">   {/* ✅ */}
<div><p className="mb-4">…</p></div>    {/* ❌ */}
```

## 9. AI에게 시킬 때

Claude Code나 다른 AI에게 화면을 만들어 달라고 할 때, **아래 형식으로 물어보면 결과가 훨씬 정확합니다.**

```
@CLAUDE.md @docs/05-개발B-join-result.md 를 읽고,
Join 화면(app/action/[id]/join/page.tsx)을 만들어줘.

지켜야 할 것:
- 데이터는 lib/queries/actions.ts 의 getActionDetail 을 쓴다
- 참여 신청은 lib/mutations.ts 의 joinAction 을 쓴다
- 모집 수량 표시는 lib/utils/quota.ts 의 getQuotaState 를 쓴다
- 새 supabase 쿼리를 직접 만들지 않는다
- params 는 Promise 이므로 await 한다
```

**핵심은 "새로 만들지 말고 있는 걸 쓰라"고 못 박는 것입니다.** 이 말이 없으면 AI가 매번 자기 방식으로 쿼리를 새로 짜서, 사람마다 다른 코드가 나옵니다.

만들어진 코드를 받으면 **8번 체크리스트를 직접 돌려보세요.** AI가 만든 코드도 실행해보기 전에는 모릅니다.

## 10. 절대 하면 안 되는 것

| 금지 | 이유 |
|---|---|
| `main`에 직접 push | 남의 작업이 사라집니다 |
| `.env.local`을 git에 올리기 | 키가 공개됩니다 |
| 키를 카톡·디스코드로 전달 | 캡처가 남고 검색됩니다 |
| 클라이언트 컴포넌트에서 `lib/openai.ts` import | 빌드가 실패합니다 (일부러 막아뒀습니다) |
| `SUPABASE_SERVICE_ROLE_KEY`에 `NEXT_PUBLIC_` 붙이기 | DB 전체가 뚫립니다 |
| Supabase 콘솔에서 테이블 직접 수정 | 다른 사람 DB와 달라집니다 |
| 상의 없이 `lib/` · `components/ui/` 수정 | 다섯 명이 동시에 충돌합니다 |
