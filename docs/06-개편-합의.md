## 문구가 이렇게 바뀝니다

모집 현황은 **조사를 생략**하는 방식으로 통일합니다. "40포**이** 더 필요해요" 같은
오타가 원천 차단되고, kg·EA·ml 같은 영문 단위에서도 문장이 자연스럽습니다.

| 상황 | 표시 |
|---|---|
| 3~5명 모집, 지금 2명 | `2 / 3~5명` · 목표까지 1명 남았어요 |
| 3~5명 모집, 지금 3명 | `3 / 3~5명` · 최소 인원을 채웠어요. 2명 더 함께할 수 있어요 |
| 3~5명 모집, 다 참 | `5 / 3~5명` · 모집이 완료됐어요. 다른 방식으로 참여해주세요 |
| 최소 10명, 지금 4명 | 목표까지 6명 남았어요 |
| 최소 10명 넘음 | 더 많은 크루가 참여할수록 좋아요 |

시간은 **24시간제로 통일**합니다 (14:00–17:00).
알림은 문서 명세대로 문구를 전면 교체하고, **나가기 알림 1종이 추가되어 7종**이 됩니다.

## 착수 전 교차 점검에서 나온 것 (2026-09-01 밤)

각 역할이 문서대로 작업한다고 가정하고 코드를 따라가 봤더니, **막히는 곳이 여섯 군데** 있었습니다.
전부 고쳐서 문서에 반영했습니다.

| 어디서 막혔을까 | 무엇이 문제였나 | 어떻게 했나 |
|---|---|---|
| 디자이너 · 홈 카드 | 카드 전체가 링크라 **좋아요 버튼을 넣으면 페이지 이동도 같이** 발생 | 덮개 링크 방식 예제를 문서에 넣음 |
| 디자이너 · 상세 | "함께하는 사람들" 아바타가 **비회원·미참여자에게 빈 배열** (RLS) | 참여자만 아바타 · 나머지는 숫자로 안내 |
| 디자이너 · 결과 보기 | 버튼이 **이미 있는데 호스트와 크루에게는 안 보임** (조건 순서) | 순서를 바꾸라고 문서에 명시 |
| 개발 A · 프로필 | `getProfile` 이 **참여 시간·알림 설정을 안 줌** → 현재 값 표시 불가 | 두 필드를 조회에 추가 |
| 개발 B · 일정별 참가자 | 크루 목록에 **참여 항목이 아예 없었음** | `getActionCrew` 확장 + `groupCrewByItem()` 추가 |
| 개발 B · 일정별 참가자 | 참여 항목이 **본인·호스트에게만** 보여 크루는 자기 것만 봄 | 사람 항목은 크루끼리 공개 (`07_update.sql`) |

그 밖에 문서의 낡은 설명 세 개도 고쳤습니다 — 나가기 3단계(이제 함수 하나), 날짜 검사(이제 함수가 처리),
