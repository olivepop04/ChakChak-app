## 1. 이 서비스가 무엇인가

**착착(CHAK CHAK)** 은 봉사·나눔 활동을 **만들고, 참여하고, 결과를 나누는** 모바일 웹 서비스입니다.
'착한 행동' 이 '착착' 풀린다는 뜻입니다.

> **📌 2026-09-01 개편 중입니다**
> 팀 의견 43건을 반영하는 중이라 화면이 조금씩 바뀝니다.
> 무엇이 정해졌고 각자 무엇을 맡았는지는 **[06-개편-합의.md](./06-개편-합의.md)** 에 있습니다.
> 이 설명서는 **지금 배포된 화면 기준**입니다. Discover 질문 3개처럼
> "곧 바뀔 예정"인 곳은 그렇게 표시해 뒀습니다.

서비스에서 다루는 활동 하나를 **액션(action)** 이라고 부릅니다. (기획 문서의 "프로젝트"가 전부 이 액션입니다.)

### 전체 흐름 한 장

```
[호스트]  액션 만들기 → AI 검수 → 공개
                                  ↓
[Crew]                        액션 발견 → 참여 신청
                                  ↓
                             크루 게시판에서 대화
                                  ↓
                             활동일이 지나감
                                  ↓
[호스트]                      결과 작성 → 공개
                                  ↓
[Crew]                        소감 남기기 → 참여 완료!
```

한 사람이 어떤 액션에서는 **호스트**(만든 사람), 다른 액션에서는 **크루**(참여한 사람)가 됩니다.

### AI가 하는 일 3가지

| | 언제 | 무엇을 |
|---|---|---|
| **검수** | 액션을 공개할 때 | 개인정보가 있는지, 설명이 충분한지 확인 |
| **추천** | Discover 화면 | 질문 3개에 답하면 어울리는 액션 3개를 골라줌 |
| **트렌드** | 트렌드 화면 | 쌓인 데이터를 읽고 눈에 띄는 점을 설명 |

> **AI가 판단해도 결정은 사람이 합니다.** 검수를 통과해도 호스트가 "액션 공개하기" 버튼을 눌러야 실제로 공개됩니다.

## 2. 준비물 설치

### 2-1. 터미널 여는 법

앞으로 `명령어`를 칠 곳이 필요합니다.

- **Windows**: 시작 → `PowerShell` 검색 → 실행
- **Mac**: `⌘ + Space` → `터미널` 검색 → 실행

> 검은 화면에 글자만 나오는 게 정상입니다. 여기에 명령을 한 줄씩 치고 `Enter` 를 누릅니다.

### 2-2. Node.js 설치

이 서비스를 실행하는 프로그램입니다. 없으면 아무것도 안 됩니다.

먼저 이미 있는지 확인해보세요.

```bash
node -v
```

- **`v20.x.x` 이상이 나오면** → 설치되어 있습니다. 2-3으로 넘어가세요.
- **아무것도 안 나오거나 `v18` 이하라면** → [nodejs.org](https://nodejs.org) 에서 **LTS** 라고 적힌 버튼을 눌러 받고, 설치 창에서 계속 "다음"만 누르면 됩니다.

> 설치 후에는 **터미널을 껐다 다시 켜야** 인식됩니다. 이걸 몰라서 "설치했는데 안 된다"고 하는 경우가 많습니다.

### 2-3. Git 설치

코드를 받아오는 도구입니다.

```bash
git --version
```

버전이 안 나오면 [git-scm.com](https://git-scm.com) 에서 받으세요. 설치 옵션은 전부 기본값으로 두면 됩니다.

### 2-4. VS Code 설치 (권장)

코드를 보고 고칠 프로그램입니다. [code.visualstudio.com](https://code.visualstudio.com)

메모장으로도 되지만 VS Code가 훨씬 편합니다. 오타도 잡아줍니다.

### 2-5. 확인

터미널을 **새로 켜서** 두 줄을 쳐보세요.

```bash
node -v
```

```bash
git --version
```

둘 다 버전이 나오면 준비 끝입니다.

## 3. 코드 받기

### 3-1. 코드를 둘 폴더로 이동

바탕화면에 두겠습니다.

```bash
cd Desktop
```

### 3-2. 코드 내려받기

```bash
git clone https://github.com/minho880910-spec/final_proj.git
```

`final_proj` 폴더가 생깁니다. 그 안으로 들어갑니다.

```bash
cd final_proj
```

> **앞으로 나오는 모든 명령은 이 폴더 안에서 칩니다.** 터미널을 새로 켰다면 `cd Desktop/final_proj` 를 먼저 치세요.

### 3-3. 필요한 라이브러리 설치

```bash
npm install
```

2~3분 걸립니다. 글자가 잔뜩 올라가다가 멈추면 끝난 것입니다.

> `npm warn` 이 여러 줄 나와도 **정상입니다.** `npm error` 만 아니면 넘어가세요.

`node_modules` 폴더가 생겼으면 성공입니다. 이 폴더는 용량이 크지만 GitHub에는 올라가지 않으니 신경 쓰지 않아도 됩니다.

### 3-4. 내 작업 브랜치로 이동

**브랜치는 이미 만들어져 있습니다.** 본인 담당에 맞는 것 하나를 고르세요.

| 담당 | 브랜치 이름 |
|---|---|
| 조장 | `feature/조장-activity` |
| 디자이너 | `feature/디자인-ui` |
| 개발 A | `feature/개발A-auth` |
| 개발 B | `feature/개발B-join` |
| 민호 | `dev` |

**세 줄을 한 세트로 돌리세요.** 본인 브랜치 이름만 바꿔 넣으면 됩니다.

```bash
git fetch origin
git checkout feature/개발A-auth
git merge origin/dev
```

> ### ⚠️ 세 번째 줄을 빼면 하루치 작업이 사라진 것처럼 보입니다
>
> 브랜치는 **만들어진 그 시점에 멈춰 있습니다.** 그 사이에 `dev` 로 올라온 작업은
> 내 브랜치에 자동으로 따라오지 않습니다.
>
> 그래서 `checkout` 만 하면 **어제 추가된 함수도, 고친 문서도 전부 없어 보입니다.**
> 코드가 지워진 게 아니라 **내 사본이 옛날 것**일 뿐입니다.
> `git merge origin/dev` 가 그 차이를 가져옵니다.
>
> **언제 돌리나** — 작업을 시작할 때마다, 그리고 민호가 "dev 갱신했어요" 라고 하면 그때.
> 자주 할수록 나중에 합칠 때 충돌이 적습니다.
>
> **`dev` 에서 직접 작업하면 안 되나요?** 안 됩니다. 네 명이 같은 브랜치에서
> 고치면 서로 덮어쓰고, PR 을 만들 수 없어서 리뷰도 못 받습니다.

> **브랜치가 뭔가요?**
> 같은 코드를 여러 명이 동시에 고치면 서로 덮어씁니다. 브랜치는 **"내 작업 사본"** 이라고 생각하시면 됩니다.
> 각자 자기 사본에서 고치고, 다 되면 합칩니다. 그래야 남의 작업이 사라지지 않습니다.

지금 어느 브랜치에 있는지 확인하려면:

```bash
git branch --show-current
```

> ⚠️ **`main` 에서는 작업하지 마세요.** `main` 은 실제 배포되는 브랜치라, 여기서 고치면 곧바로 인터넷에 올라갑니다.

## 4. 최초 환경설정

서비스가 데이터베이스와 AI에 접속하려면 **비밀번호 같은 값 4개**가 필요합니다.

### 4-1. 설정 파일 만들기

견본 파일을 복사합니다.

```bash
cp .env.local.example .env.local
```

> PowerShell 이라면: `copy .env.local.example .env.local`

### 4-2. 채워야 할 값 4개

VS Code에서 **`.env.local`** 파일을 엽니다. 이렇게 생겼습니다.

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGci...
SUPABASE_SERVICE_ROLE_KEY=eyJhbGci...
OPENAI_API_KEY=sk-...
```

`=` 뒤의 가짜 값을 진짜 값으로 바꾸면 됩니다. **각 값을 어디서 구하는지 아래에 순서대로 적었습니다.**

| 값 | 어디서 | 누가 |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase 대시보드 | 각자 복사 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase 대시보드 | 각자 복사 |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase 대시보드 | 각자 복사 (취급 주의) |
| `OPENAI_API_KEY` | OpenAI 대시보드 | **각자 발급** |

### 4-3. Supabase 값 3개 가져오기

**① 민호에게 프로젝트 초대를 받으세요**

초대 메일이 오면 수락합니다. 이게 있어야 대시보드가 보입니다.

> 아직 초대를 못 받았다면 민호에게 **Supabase 가입에 쓸 이메일**을 알려주세요.

**② [supabase.com/dashboard](https://supabase.com/dashboard) 접속 → 프로젝트 선택**

프로젝트 이름은 `dongaAI_final_proj` 입니다.

**③ 왼쪽 맨 아래 톱니바퀴(⚙ Project Settings) → `API`**

이 화면에 세 가지가 다 있습니다.

```
Project URL
  https://xxxxxxxx.supabase.co        ← NEXT_PUBLIC_SUPABASE_URL

Project API keys
  anon  public                        ← NEXT_PUBLIC_SUPABASE_ANON_KEY
  eyJhbGc●●●●●●●●●●●●●●●●●●●●●●●●●●●  (아주 긴 글자)

  service_role  secret   [Reveal]     ← SUPABASE_SERVICE_ROLE_KEY
  ●●●●●●●●●●●●●●●●●●●●●●●●●●●
```

**④ 각 값 오른쪽의 복사 아이콘(⧉)을 눌러 복사한 뒤 `.env.local` 에 붙여넣으세요.**

`service_role` 은 가려져 있습니다. **`Reveal`** 을 눌러야 보입니다.

> 💡 **한 줄로 붙어야 합니다.** 키가 길어서 줄바꿈이 들어가면 인식되지 않습니다. VS Code에서 값이 한 줄로 이어져 있는지 확인하세요.
>
> 그리고 `=` 앞뒤에 **띄어쓰기를 넣지 마세요.** `KEY = 값` (❌) / `KEY=값` (✅)

#### 세 값의 차이

| 값 | 성격 |
|---|---|
| `URL` | 우리 데이터베이스 주소. 공개돼도 상관없습니다 |
| `anon` | 브라우저에서 쓰는 열쇠. **공개돼도 괜찮게 설계**돼 있습니다. 이 열쇠로는 권한(RLS) 규칙을 못 넘습니다 |
| `service_role` | **모든 잠금을 여는 마스터 열쇠.** 권한 규칙을 전부 무시합니다 |

> ⚠️ **`service_role` 은 절대 유출되면 안 됩니다.** 이 키가 있으면 누구나 우리 DB의 모든 데이터를 읽고 지울 수 있습니다.
>
> 이 프로젝트에서 이 키는 **서버 안에서만** 쓰이고, `npm run seed` · `npm run verify:db` 같은 로컬 명령에서만 필요합니다. 브라우저로는 절대 나가지 않습니다.
>
> 그래서 **`NEXT_PUBLIC_` 을 붙이면 절대 안 됩니다.** 붙이는 순간 브라우저로 전송됩니다.

#### ⚠️ 키는 본인 것만 쓰세요

**남의 키를 빌려 쓰거나, 본인 키를 남에게 주지 마세요.**

- 사용량이 섞여서 누가 얼마를 썼는지 알 수 없게 됩니다
- 한 사람 키가 새면 그 키를 쓰던 사람들이 전부 멈춥니다

그리고 **키를 카톡·디스코드·GitHub 에 절대 올리지 마세요.** 캡처가 남고, 대화방은 검색되고, GitHub 은 자동으로 훑는 봇이 돌아다닙니다.

#### 키가 아직 없다면

**AI 없이도 대부분의 화면은 잘 동작합니다.** AI가 필요한 곳은 세 군데뿐입니다.

| 화면 | 키가 없으면 |
|---|---|
| 액션 공개할 때 검수 | 개인정보·날짜 검사는 그대로 되고, AI 품질 검사만 건너뜁니다 |
| Discover 추천 | 추천 카드는 나오고 **이유만** 기본 문구로 나옵니다 |
| 트렌드 해설 | **그래프는 나오고** 해설 자리만 빕니다 |

본인 담당이 이 세 곳이 아니라면 **`OPENAI_API_KEY` 는 비워 둬도 개발에 아무 지장이 없습니다.** 나중에 필요할 때 넣으세요.

### 테스트 B. 액션 상세 화면 자세히 보기 (5분)

액션 상세에서 **모집 현황**을 보세요. **두 가지 방식이 다르게 표시됩니다.**

```
산책 도우미     최소 5명
3명 참여   ▓▓▓▓▓▓░░░░   목표까지 2명 남았어요            ← 퍼센트를 안 씀

산책 봉사자     3~6명
4 / 3~6명  ▓▓▓▓▓▓▓░░░   최소 인원을 채웠어요. 2명 더 함께할 수 있어요
```

> ✅ **확인 포인트:** 이게 이 프로젝트에서 제일 중요한 규칙입니다.
>
> **① "최소 N명" 방식은 퍼센트를 쓰지 않습니다.** 상한이 없어서 15명이 와도 150%라고 하면 의미가 없습니다.
>
> **② "N~M명" 방식은 분모가 `3~6명` 으로 끝까지 고정입니다.** 예전에는 최소를 넘기면
> 분모가 `3` 에서 `6` 으로 바뀌었는데, 숫자가 갑자기 변해서 헷갈린다는 지적을 받아 2026-09-01 에 바꿨습니다.
>
> **③ 변수 뒤에 조사를 붙이지 않습니다.** "40포**이** 더 필요해요" 같은 오타가 나고,
> `kg` `EA` `ml` 같은 영문 단위에서는 조사 규칙 자체가 없습니다.
> 그래서 **"목표까지 40포 남았어요"** 처럼 조사가 안 붙는 문장만 씁니다.

여러 액션을 열어보면서 **하단 버튼이 상황마다 다른 것**도 봐주세요.

| 상황 | 버튼 |
|---|---|
| 내가 만든 액션 | `내가 만든 액션` |
| 이미 참여한 액션 | `CREW CHAT으로 가기` |
| 모집이 다 찬 액션 | `모집이 완료되었어요` (안 눌림) |
| 취소된 액션 | `취소된 액션이에요` + 취소 사유 |
| 그 외 | `참여하기` |

### 테스트 D. 액션 만들고 공개하기 (10분) ⭐

가장 볼거리가 많은 흐름입니다. 로그인한 상태에서 하단 탭 **`＋`** 를 누르세요.

**① 제목을 적고 아래 `저장` 을 누릅니다**

- 주소가 `/action/create?id=...` 로 바뀝니다
- **사진 올리는 칸이 열립니다**

> 왜 저장을 먼저 해야 하나요? 사진은 "어느 액션의 사진인지" 정해져야 저장할 수 있어서, 액션이 먼저 만들어져야 합니다.

**💾 저장:** `actions` 테이블에 `status = 'DRAFT'` (작성 중) 상태로 한 줄

**② 사진을 올립니다**

아무 사진이나 고르세요.

> ✅ **확인 포인트:** 5MB짜리 사진을 올려도 **자동으로 가로 1200px · WebP로 줄여서** 200~300KB로 저장됩니다. 무료 저장 공간이 1GB뿐이라 이렇게 해뒀습니다.

**💾 저장:** 파일은 Storage의 `action-images` 폴더, 주소는 `actions.image_urls`

**③ 모집 항목을 추가합니다** — `＋ 사람` 또는 `＋ 물품`

두 가지 방식 중에 고릅니다.

- **정해진 수량이 필요해요** → 최소 3명 ~ 최대 5명
- **최소 수량만 정할게요** → 최소 10명 (상한 없음)

> 최소와 최대를 **같은 숫자**로 하면 화면에 **"정확히 3명"** 으로 표시됩니다.

사람 항목에는 **성별 조건**(남성만 / 여성만 / 누구나)도 정할 수 있습니다. 남성 어르신 목욕 봉사처럼 필요한 경우가 있어서입니다.

**④ 날짜 3개와 장소를 채웁니다**

- 모집 마감 · 활동 시작 · 활동 종료 — **셋 다 다른 값입니다**
- 모집 마감은 활동 시작보다 앞서야 합니다

**⑤ `액션 생성하기` 를 누릅니다 → AI 검수가 돕니다** ⭐

**여기서 일부러 오류를 내보세요.** 소개글에 전화번호를 넣고 공개해보세요.

```
연락처는 010-1234-5678 로 주세요
```

→ **빨간 상자**가 뜨고 `액션 공개하기` 버튼이 **나타나지 않습니다.**

```
⚠️ 공개하기 전에 고쳐야 할 것이 있어요
   · 본문에 전화번호가 있어요. 개인정보는 빼주세요.
```

전화번호를 지우고 다시 누르면 통과합니다.

> ✅ **확인 포인트:** 전화번호·이메일 검사는 **AI가 아니라 코드가** 합니다. 정규식이 더 정확하고 빠르고 공짜니까요. AI는 "설명이 충분한가", "취지에 맞는가" 같은 걸 봅니다.

**⑥ `액션 공개하기` 를 누릅니다**

> ✅ **확인 포인트:** AI가 통과시켜도 **자동으로 공개되지 않습니다.** 사람이 마지막에 한 번 더 눌러야 합니다. 발표 때 설명하기 좋은 부분입니다.

**💾 저장:**
- `actions.status` 가 `ACTIVE` 로 바뀜
- AI 검수 결과 → `ai_runs` 테이블 + `actions.review_feedback`
- AI 분류 색인 → `action_ai_metadata` 테이블 (Discover 추천이 이걸 검색합니다)

이제 홈으로 가면 **내가 만든 액션이 목록에 보입니다.**

### 테스트 E. 다른 계정으로 참여하기 (10분) ⭐

**시크릿 창**(`Ctrl + Shift + N`)을 열고 `localhost:3000` 으로 갑니다. 여기서 **다른 계정**으로 로그인하세요.

방금 만든 액션을 찾아 **`참여하기`** 를 누릅니다.

**① 항목을 고릅니다**

- 물품 항목은 **수량 입력**이 나옵니다 (`− 10 ＋`, 직접 타이핑도 됩니다)
- 사람 항목은 수량이 없습니다 (항상 1명)
- 성별이 안 맞는 항목은 **체크가 안 되고** 이유가 표시됩니다
- 다 찬 항목도 **체크가 안 됩니다**

**② 아래 `나의 참여` 요약을 확인하고 `참여 확정하기`**

**💾 저장:**
- `participations` 테이블에 한 줄 (`status = 'BEFORE_ACTION'`)
- `participation_items` 테이블에 고른 항목마다 한 줄

**③ 축하 화면이 뜹니다** → `함께하는 사람들` 을 눌러 크루 목록도 보세요

> ✅ **확인 포인트 (가장 중요):**
> 화면에 "1명 더 함께할 수 있어요"라고 보여도 **서버가 다시 확인합니다.** 두 사람이 동시에 마지막 자리를 신청하면 둘 다 자리가 있는 것으로 보이거든요. 그래서 실제 판단은 데이터베이스가 순서대로 처리합니다.
>
> 직접 확인해보려면 **정원이 1명인 항목**을 만들고, 두 계정으로 신청해보세요. 두 번째는 이렇게 거절됩니다.
> ```
> 「산책 도우미」 모집이 완료되었습니다. (1 / 1)
> ```

**④ 원래 창(호스트 계정)으로 돌아가 액션을 새로고침하면 숫자가 늘어나 있습니다.**

## 9. 버튼 → 저장되는 곳 지도

**"이걸 누르면 어디에 뭐가 저장되나"** 를 한 표로 정리했습니다.

| 무엇을 하면 | 어느 테이블에 | 비고 |
|---|---|---|
| 가입 완료 | `auth.users` + `profiles` | 트리거가 profiles를 자동 생성 |
| 프로필 수정 | `profiles` | 이름·성별은 수정 불가 |
| ♥ 좋아요 | `likes` | 다시 누르면 삭제 |
| 🔖 저장 | `saves` | 다시 누르면 삭제 |
| 팔로우 | `follows` | 다시 누르면 삭제 |
| 액션 `저장` | `actions` (DRAFT) + `action_items` | 아직 아무에게도 안 보임 |
| 사진 업로드 | Storage `action-images` + `actions.image_urls` | 올리는 즉시 저장됨 |
| `액션 생성하기` (검수) | `ai_runs` + `actions.review_feedback` | 상태는 안 바뀜 |
| `액션 공개하기` | `actions.status` → ACTIVE, `action_ai_metadata` | 이때부터 남에게 보임 |
| `참여 확정하기` | `participations` + `participation_items` | 서버가 정원·성별 검증 |
| `나가기` | `participations.status` → LEFT | 행은 남고 집계에서만 빠짐 |
| 게시판 글·댓글 | `chat_messages` | |
| 게시판 삭제 | `chat_messages.deleted_at` | 원글 지우면 댓글도 함께 |
| `결과 공개하기` | `action_results` + `actions.status` → COMPLETED + `notifications` | 참여자 전원에게 알림 |
| `소감 남기기` | `crew_voices` + `participations.status` → ACTUALLY_PARTICIPATED | 둘이 함께 저장됨 |
| 공유 `보내기` | `notifications` | 상대에게 초대 알림 |
| 알림 클릭 | `notifications.is_read` | 읽음 처리 후 이동 |
| `취소하기` | `actions.status` → CANCELLED + `notifications` | 사유 5자 이상 필수 |
| DRAFT `삭제하기` | `actions` 행이 **진짜 삭제됨** | 공개된 적 없으니 남길 게 없음 |
| Discover 추천 | `ai_runs` (2건: 필터 + 이유) | |
| 트렌드 열람 | `ai_runs` (1건) | |

### 저장되지 않는 것

| | 왜 |
|---|---|
| 로그인 상태 | 브라우저 쿠키에만 (서버는 확인만) |
| 참여 인원 수 | **저장하지 않고 매번 계산합니다.** 저장하면 실제 참여와 숫자가 어긋날 수 있어서요 |
| 검색어 · 필터 | 주소(URL)에만 |

### 왼쪽 메뉴에서 볼 것

| 아이콘 | 이름 | 여기서 보는 것 |
|---|---|---|

### 자주 보게 될 테이블

```
actions              액션 (제목·상태·날짜)
action_items         모집 항목 (최소/최대 수량)
participations       누가 어느 액션에 참여했나
participation_items  무엇을 얼마나 하기로 했나
chat_messages        게시판 글
crew_voices          소감
notifications        알림
ai_runs              AI를 부른 기록 ⭐
profiles             사용자 정보
```

### 해보면 좋은 확인

**① 방금 만든 액션 찾기**

`Table Editor` → `actions` → 맨 위에 있습니다 (최근 것이 위)

`status` 칸이 `DRAFT` 인지 `ACTIVE` 인지 보세요. 공개 버튼을 누르기 전후로 값이 바뀝니다.

**② AI를 부른 기록 보기** ⭐

`Table Editor` → `ai_runs`

```
agent_type   REVIEW / CLASSIFY / DISCOVER / TRENDS  — 어떤 AI인지
status       SUCCESS / API_FAIL / SCHEMA_FAIL       — 성공했는지
latency_ms   걸린 시간
prompt_version  프롬프트 버전
```

> **발표에서 쓸 자료가 여기 있습니다.** `prompt_version` 을 보면 `trends-v1` 과 `trends-v2` 가 같이 있습니다.
> v1은 AI가 없는 통계를 만들어냈고, 원인을 찾아 고친 게 v2입니다. **"어떻게 검증하고 개선했는가"** 를 이 표로 보여줄 수 있습니다.

**③ 게시판 삭제가 진짜 삭제가 아닌 것 확인**

`chat_messages` → 삭제한 글을 찾아보세요. 행이 그대로 있고 `deleted_at` 에만 시각이 들어 있습니다.

## 12. 문제가 생기면

### 화면이 하얗게 뜨거나 목록이 계속 비어 있어요

**십중팔구 권한(RLS) 설정입니다.** 에러가 안 나고 조용히 빈 결과가 오기 때문에 찾기 어렵습니다.

1. 로그인은 되어 있나요?
2. 그 데이터를 볼 자격이 있나요? (게시판은 참여자만 볼 수 있습니다)
3. 그래도 이상하면 민호에게 **어느 화면인지** 알려주세요

### `npm run dev` 가 안 되고 포트 어쩌고 나와요

```
Error: listen EADDRINUSE: address already in use :::3000
```

이미 서버가 켜져 있다는 뜻입니다. 다른 번호로 켜세요.

```bash
npm run dev -- -p 3001
```

### 화면이 깨지거나 이상하게 나와요

임시 파일이 꼬인 것입니다. 지우고 다시 켜면 대부분 해결됩니다.

```bash
rm -rf .next
```

```bash
npm run dev
```

### `Module not found` 가 나와요

라이브러리가 덜 깔린 것입니다.

```bash
npm install
```

그래도 안 되면 통째로 지우고 다시 설치합니다.

```bash
rm -rf node_modules package-lock.json
```

```bash
npm install
```

### `npm run build` 가 실패해요

타입 오류입니다. 메시지에 위치가 나옵니다.

```
app/my/page.tsx(42,15): error TS2339: ...
        ↑ 파일     ↑줄  ↑글자
```

그 줄을 보세요. 가장 흔한 원인은 **비어 있을 수 있는 값을 그냥 쓴 것**입니다.

```tsx
{profile.name}        // ❌ profile 이 없을 수도 있음
{profile?.name}       // ✅
{profile?.name ?? '이름 없음'}  // ✅ 더 좋음
```

### AI 기능만 안 돼요

`.env.local` 의 `OPENAI_API_KEY` 를 확인하세요. 값을 고쳤다면 **서버를 껐다 켜야** 적용됩니다 (`Ctrl+C` → `npm run dev`).

### git에서 충돌(conflict)이 났어요

**혼자 해결하려다 남의 코드를 지우는 일이 자주 생깁니다.** 민호에게 캡처와 함께 물어보세요.

급하면 되돌릴 수 있습니다. (내가 병합하려던 것도 취소됩니다)

```bash
git merge --abort
```

### 그래도 모르겠으면

팀 채팅에 **세 가지**를 함께 올려주세요. 이게 있으면 대부분 몇 분 안에 풀립니다.

1. 무엇을 하려고 했는지
2. **오류 메시지 전체** 캡처 (일부만 자르지 마세요)
3. 어느 파일 · 어느 화면인지
