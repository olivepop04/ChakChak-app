### 과제 3. ★ 여러 번 고치면서 남은 찌꺼기를 찾으세요 (이번 감사의 중점)

하루에 네 번 DB 를 바꾸고 문서를 열 개 넘게 고쳤습니다.
**쓰이지 않는데 남아 있는 것**이 반드시 있습니다. 다음을 전부 확인하세요.

**(가) 죽은 코드**
 - export 했는데 아무 데서도 import 하지 않는 함수·상수·타입
 - 정의만 있고 호출되지 않는 함수
 - 같은 일을 하는 함수가 둘 이상 (예: 구버전과 신버전이 함께 남아 있는가)
 - 주석 처리된 코드 뭉치
 - 사용하지 않는 import

**(나) 죽은 파일**
 - 어디서도 참조되지 않는 파일
 - 임시·실험 파일 (scratch·temp·backup·old 같은 이름, .bak, 숫자만 붙은 사본)
 - .gitignore 에 있어야 하는데 추적되고 있는 파일
 - 반대로, 필요한데 실수로 .gitignore 된 파일

**(다) 죽은 스키마**
 - "이제 안 쓴다"고 표시했는데 여전히 코드가 읽는 컬럼
 - 마이그레이션에서 만들었는데 아무 데서도 안 쓰는 컬럼·테이블·인덱스
 - 앞 마이그레이션이 만든 것을 뒤 마이그레이션이 덮어써서, 앞 파일이 무의미해진 곳
 - 실행하면 안 되는데 목록에 남아 있는 SQL 파일

**(라) 죽은 문서**
 - 지금은 틀린 설명 (특히 "곧 바뀔 예정"이라고 적어둔 것이 이미 바뀌었는지)
 - 같은 내용이 두 문서에 중복돼서 한쪽만 고쳐질 위험이 있는 곳
 - 더 이상 존재하지 않는 파일·함수·화면을 가리키는 링크
 - 완료된 작업이 여전히 "할 일"로 적혀 있는 곳
 - 이미 지나간 안내 (예: "민호 작업이 끝나면 시작하세요")

**(마) 죽은 검증**
 - verify-db 가 이제 존재하지 않는 것을 검사하고 있는가
 - 같은 것을 두 번 검사하는가
 - 통과하지만 아무것도 보장하지 않는 검사가 있는가

각 항목에 대해 **지워도 되는지 / 살려야 하는지**를 근거와 함께 판단해주세요.
"안 쓰이니까 지우자"가 항상 맞지는 않습니다 —
곧 쓸 예정이거나, 발표 증거로 남겨둔 것일 수 있습니다.

## 검증 결과를 받은 뒤

돌아온 지적을 그대로 믿지 마세요. **AI도 틀립니다.**
1차 감사에서 실제로 나왔던 오탐입니다.

- `insert` · `cookies` · `refresh` 같은 **라이브러리 메서드**를 "없는 함수"라고 하는 경우
- `GOODS`(물품 항목 코드값)를 옛 서비스명 `GOOD`으로 오해하는 경우
- 문서가 "이 파일은 건드리지 마세요"라고 **경고**한 것을 담당 위반으로 세는 경우
- 비회원에게 참여자 명단이 안 보이는 것을 버그로 보는 경우 (**의도된 규칙**입니다)
- 화면에 안 보이는 **주석 속 영문**을 "노출됐다"고 하는 경우
- 인용한 파일명·줄번호가 실제와 다른 경우 (1차에서 3건 있었습니다)

**잔재 판정은 특히 조심하세요.** 아래는 일부러 남겨둔 것입니다.

- `ai_runs` 의 옛 프롬프트 버전 기록 — **발표에서 "이렇게 개선했다"의 증거**
- `AVAILABLE_TIMES` · `profiles.available_times` — 추천 점수가 아직 씀. 개발 A 가 옮긴 뒤에 제거
- DB 의 `leave_action` RPC — 화면에서는 안 쓰지만 `verify:db` 의 시간 검사 테스트가 씀.
