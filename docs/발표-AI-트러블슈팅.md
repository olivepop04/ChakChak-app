# 발표 자료 — AI를 어디까지 믿을 것인가

> 착착(CHAK CHAK)이 AI를 쓰면서 **직접 겪은 문제와 그 해결**을 정리한 문서입니다.
> 발표의 "검증·개선" 항목에 그대로 쓸 수 있게 썼습니다.
>
> **핵심 한 줄** — AI에게 **판단**을 맡기고, **사실**은 코드가 보장했습니다.

---

## 1. 우리가 정한 원칙

AI를 쓰는 팀은 많습니다. 문제는 **어디까지 맡기느냐**입니다.

저희는 처음부터 선을 그었습니다. 실제로 `lib/utils/scoring.ts` 맨 위에 이렇게 적혀 있습니다.

```
★ 점수는 코드가 계산합니다. AI 는 의도 해석과 추천 이유 설명만 합니다.
  AI 에게 순위를 매기게 하면 매번 결과가 달라져서 검증할 수 없습니다.
```

### 역할 분담

| 하는 일 | 누가 | 왜 |
|---|---|---|
| 사용자의 말에서 **조건을 뽑아내기** | **AI** | "주말에 몸 쓰는 거"를 카테고리·시간으로 옮기는 건 규칙으로 못 짬 |
| 조건에 맞는 **후보 고르기** | **코드** | 틀리면 안 되는 일. 아래 참고 |
| 후보에 **점수 매기기** | **코드** | 배점이 고정이라 언제 돌려도 같은 결과 |
| 추천 **이유 설명하기** | **AI** | 사람이 읽을 문장. 조금씩 달라도 괜찮음 |
| 액션 글 **검수하기** | **AI** | 판단이 필요한 일 |
| 검수 결과로 **공개 여부 결정** | **사람** | AI는 의견만. 최종 결정은 호스트 |

**규칙 하나로 요약됩니다.**

> **틀리면 안 되는 것은 코드가, 사람이 읽을 것은 AI가.**

---

## 2. 후보 선정을 AI에게 맡기면 생기는 일

추천 후보를 AI가 직접 고르게 하는 방식도 있습니다. 저희는 **안 했습니다.**

| | AI가 후보까지 고르면 | 코드가 고르면 |
|---|---|---|
| 이미 마감된 액션 | **추천할 수 있음** | 절대 안 나옴 |
| 존재하지 않는 액션 | **지어낼 수 있음** | 불가능 |
| 내가 이미 참여한 액션 | **또 추천할 수 있음** | 제외됨 |
| 내가 만든 내 액션 | **추천할 수 있음** | 제외됨 |
| 같은 조건으로 다시 물으면 | **결과가 달라짐** | 항상 같음 |

마지막 줄이 특히 중요합니다.

**AI가 순위를 매기면 같은 조건에서도 매번 다른 답이 나옵니다.** 그러면 "이 추천이 맞는지" 확인할 방법이 없습니다. **테스트를 짤 수 없는 기능**이 됩니다.

지금 구조에서는 `getRecommendCandidates()`가 **마감·참여 중·본인 액션을 먼저 걸러내고**, `scoreAction()`이 **고정된 배점으로** 점수를 매깁니다. AI는 그 결과를 받아서 이유만 씁니다.

```
사용자의 말
   ↓  AI — 조건 뽑기
{ 카테고리: 환경, 지역: 성동구, 시간: 주말 }
   ↓  코드 — 후보 거르기 (마감·중복·본인 제외)
후보 12개
   ↓  코드 — 점수 매기기 (30/25/20/15/10)
상위 5개
   ↓  AI — 이유 쓰기
"주말에 가까운 데서 몸 쓰는 활동을 찾으셨죠. 성수동이라 가깝고..."
```

**AI가 두 번 등장하지만, 두 번 다 사실을 만들어내지 않습니다.**

## 3. 실제로 겪은 문제 3건

원칙만 세운 게 아니라 **실제로 당하고 고쳤습니다.** 기록이 `ai_runs` 테이블에 남아 있습니다.

### 사례 ① — 화면은 멀쩡한데 AI가 한 번도 안 돌았다

**증상.** Discover 추천 이유가 계속 기본 문구로 나왔습니다. 에러도 없고 화면도 정상이라 **한동안 몰랐습니다.**

**원인.** OpenAI에 JSON 형식으로 답하라고 요청할 때, **프롬프트 본문에 "json"이라는 낱말이 없으면 400을 돌려줍니다.** 저희 프롬프트에 그 단어가 없었습니다.

**어떻게 찾았나.** `ai_runs`에 `discover-reason-v1`이 전부 `API_FAIL`로 쌓여 있었습니다. 화면에는 안 보이는 실패였습니다.

**고친 방법.** 프롬프트에 문장을 넣고, 재발을 막기 위해 **공통 함수에서 자동으로 검사**하도록 했습니다. 프롬프트에 "json"이 없으면 알아서 붙입니다.

> **배운 것** — 조용히 실패하는 게 가장 위험합니다. 로그가 없었으면 발표 당일까지 몰랐을 겁니다.

### 사례 ② — AI가 없는 숫자를 지어냈다

**증상.** 트렌드 대시보드에 **"참여 완료율 64%"**가 떴습니다. 저희는 그런 지표를 준 적이 없습니다.

**원인.** AI에게 넘긴 필드 이름이 모호했습니다. `completed`, `participants` 같은 이름을 보고 **AI가 둘을 나눠서 없는 비율을 만들어냈습니다.**

**고친 방법.** 두 가지를 했습니다.

1. 필드 이름을 **문장처럼** 바꿨습니다 — `completed` → `소감까지_남긴_참여자_수`
2. 프롬프트에 **"주어진 숫자만 쓰세요. 새 비율을 계산하지 마세요"**를 넣었습니다

그리고 `trends-v1` → `trends-v2`로 **버전을 올렸습니다.**

> **배운 것** — AI는 필드 이름을 보고 의미를 추측합니다. 이름이 애매하면 **없는 관계를 만들어냅니다.**

### 사례 ③ — 애초에 맡기지 않기로 한 것

앞의 둘은 겪고 고쳤지만, 이건 **처음부터 안 맡겼습니다.**

후보 선정을 AI에게 넘겼다면 위 두 사례와 같은 종류의 문제가 **추천 결과에서** 났을 겁니다. 다만 이번엔 훨씬 나쁩니다 — **마감된 액션을 추천받은 사용자가 신청하러 갔다가 거절당하는** 일이 생깁니다.

사례 ①·②를 겪고 나서 이 결정이 옳았다는 걸 확인했습니다.

## 4. 어떻게 확인하고 있나

AI 호출을 **전부 기록합니다.** `ai_runs` 테이블입니다.

| 컬럼 | 담는 것 |
|---|---|
| `agent_type` | REVIEW · CLASSIFY · DISCOVER · TRENDS |
| `prompt_version` | `trends-v1`, `trends-v2` … **프롬프트를 고치면 반드시 올림** |
| `status` | SUCCESS · SCHEMA_FAIL · API_FAIL · RETRY_OK |
| `error_code` | 실패했을 때 이유 |
| `latency_ms` | 응답에 걸린 시간 |
| `output_json` | AI가 실제로 돌려준 것 |

**버전별로 성공·실패가 쌓입니다.** 그래서 "고치기 전에는 이랬고, 고친 뒤에는 이렇다"를 숫자로 보여줄 수 있습니다.

```sql
-- 발표 직전에 이걸 돌리면 표가 나옵니다
SELECT prompt_version, status, count(*)
FROM ai_runs
GROUP BY prompt_version, status
ORDER BY prompt_version;
```

> **초기 버전 로그를 지우지 마세요.** `discover-reason-v1`의 실패 기록과 `trends-v1`의 잘못된 출력이 **개선을 보여주는 증거**입니다.

## 5. 발표에서 이렇게 말하면 됩니다

**슬라이드 1 — 문제 제기**

> AI를 붙이는 건 어렵지 않았습니다.
> **어디까지 맡길지 정하는 게 어려웠습니다.**

**슬라이드 2 — 역할 분담 표** (위 1번 표)

> 저희는 이렇게 나눴습니다.
> **틀리면 안 되는 것은 코드가, 사람이 읽을 것은 AI가.**

**슬라이드 3 — 왜 그렇게 나눴나** (위 2번 표)

> 추천 후보를 AI가 고르게 하면 **마감된 액션을 추천할 수 있습니다.**
> 그리고 같은 조건에서 매번 다른 답이 나와서 **테스트를 짤 수 없습니다.**

**슬라이드 4 — 실제로 겪은 것**

> 두 번 당했습니다.
> 한 번은 **AI가 아예 안 돌고 있었는데 화면은 멀쩡했고**,
> 한 번은 **AI가 없는 숫자를 지어냈습니다.**
> 둘 다 로그가 있어서 찾았습니다.

**슬라이드 5 — 개선 결과** (`ai_runs` 쿼리 결과 표)

> 프롬프트 버전을 올려가며 고쳤고, **기록이 남아 있습니다.**

## 6. 예상 질문과 답

**"AI가 잘못된 추천을 하면요?"**
> 후보 선정은 코드가 합니다. AI는 이미 걸러진 목록에 이유만 씁니다.
> 이유 문장이 어색할 수는 있어도 **없는 액션이나 마감된 액션이 나오지는 않습니다.**

**"AI 응답이 실패하면 화면이 깨지나요?"**
> 아니요. 실패하면 **기본 문구로 대체**하고 넘어갑니다. 실패 기록은 남습니다.
> 사례 ①이 정확히 그 상황이었습니다 — 사용자는 아무 문제를 못 느꼈습니다.

**"왜 GPT-4o-mini인가요?"**
> 저희가 AI에게 맡긴 일이 **판단과 문장 쓰기**라 큰 모델이 필요 없습니다.
> 정확해야 하는 계산은 어차피 코드가 합니다.

**"프롬프트를 어떻게 관리하나요?"**
> 고칠 때마다 버전을 올립니다. `trends-v1` → `trends-v2`.
> `ai_runs`에 버전이 함께 저장돼서 **어느 버전이 몇 번 실패했는지** 볼 수 있습니다.
